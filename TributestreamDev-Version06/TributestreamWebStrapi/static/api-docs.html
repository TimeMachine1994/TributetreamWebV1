TributeStream API Documentation

This documentation provides details about the available API endpoints for the TributeStream application.

Authentication

POST /api/auth

Authenticates a user and returns user data with JWT token in an HTTP-only cookie.

Authentication

Public

Request Body

{
  "identifier": "email@example.com", 
  "password": "password123"
}

Response

{
  "user": {
    "id": 1,
    "username": "username",
    "email": "email@example.com",
    ...
  },
  "success": true
}
POST /api/auth/register

Registers a new user and returns user data with JWT token in an HTTP-only cookie.

Authentication

Public

Request Body

{
  "username": "username",
  "email": "email@example.com",
  "password": "password123"
}

Response

{
  "user": {
    "id": 1,
    "username": "username",
    "email": "email@example.com",
    ...
  },
  "success": true
}

Users

GET /api/users/me

Gets the current authenticated user's data.

Authentication

Requires JWT cookie (authenticated user)

Query Parameters

?populate=contactInfo - Include related contact information

Response

{
  "user": {
    "id": 1,
    "username": "username",
    "email": "email@example.com",
    "contactInfo": {
      ...
    },
    ...
  },
  "success": true
}

Tributes

GET /api/tributes

Gets a list of all tributes, with optional filtering.

Authentication

Public

Query Parameters

?populate=deep - Include all related data

?filters[lovedOnesFullName][$containsi]=John - Filter by name containing "John"

?filters[owner][id]=1 - Filter by owner ID

Response

{
  "data": [
    {
      "id": 1,
      "attributes": {
        "lovedOnesFullName": "Jane Doe",
        "slug": "jane-doe",
        ...
      }
    },
    ...
  ],
  "meta": {
    "pagination": {
      "page": 1,
      "pageSize": 25,
      "pageCount": 1,
      "total": 5
    }
  }
}
POST /api/tributes

Creates a new tribute.

Authentication

Requires JWT cookie (authenticated user)

Request Body

{
  "data": {
    "lovedOnesFullName": "Jane Doe",
    "slug": "jane-doe"
  }
}

Response

{
  "data": {
    "id": 1,
    "attributes": {
      "lovedOnesFullName": "Jane Doe",
      "slug": "jane-doe",
      ...
    }
  },
  "success": true
}
GET /api/tributes/:id

Gets a specific tribute by ID.

Authentication

Public

Path Parameters

:id - The ID of the tribute

Query Parameters

?populate=deep - Include all related data

Response

{
  "data": {
    "id": 1,
    "attributes": {
      "lovedOnesFullName": "Jane Doe",
      "slug": "jane-doe",
      ...
    }
  },
  "meta": {}
}
PUT /api/tributes/:id

Updates a specific tribute.

Authentication

Requires JWT cookie (authenticated user)

Path Parameters

:id - The ID of the tribute

Request Body

{
  "data": {
    "lovedOnesFullName": "Jane Smith",
    "paymentComplete": true
  }
}

Response

{
  "data": {
    "id": 1,
    "attributes": {
      "lovedOnesFullName": "Jane Smith",
      "paymentComplete": true,
      ...
    }
  },
  "success": true
}
DELETE /api/tributes/:id

Deletes a specific tribute.

Authentication

Requires JWT cookie (authenticated user)

Path Parameters

:id - The ID of the tribute

Response

{
  "data": {
    "id": 1,
    "attributes": {
      "lovedOnesFullName": "Jane Doe",
      ...
    }
  },
  "success": true
}

Testing API Endpoints

To test these API endpoints, you can use:

  • Command line tools like curl
  • API testing tools like Postman or Insomnia

Example curl commands:

Register User:

curl -X POST http://localhost:5173/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"username":"test","email":"test@example.com","password":"test123"}'

Create Tribute:

curl -X POST http://localhost:5173/api/tributes \
  -H "Content-Type: application/json" \
  -d '{"data":{"lovedOnesFullName":"Jane Doe","slug":"jane-doe"}}'

Mark Payment Complete:

curl -X PUT http://localhost:5173/api/tributes/1 \
  -H "Content-Type: application/json" \
  -d '{"data":{"paymentComplete":true}}'
